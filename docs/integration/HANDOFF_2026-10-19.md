### New and changed routes

| Route | Who | Behaviour |
|---|---|---|
| `POST /api/v1/me/conversations` (`openOwnConversation`) | customer | **409 `CONVERSATION_ALREADY_OPEN`** while one is queued, assigned, active or escalated; the message names it |
| `POST /api/v1/conversations` (front desk) | staff | Same rule for the customer it opens for |
| `DELETE /api/v1/me/conversations/{id}` (`deleteOwnConversation`) | customer | 204. A live conversation ends as ABANDONED; escalated: **409 `CONVERSATION_UNDER_SUPERVISION`**; not theirs or already removed: 404. The bank keeps the record |
| `GET /api/v1/conversations/accessible` | all | Items gain `counterpartName` (advisor for a customer, `null` while waiting; customer for staff), `subject` (French), `removedByCustomer` |
| `POST /api/v1/customers` (`onboardCustomer`) | advisor, supervisor, admin | 201 `{customerId, email, externalRef, maskedIban, cardLast4}`. One transaction; taken e-mail: **409 `EMAIL_ALREADY_USED`**, nothing written. Current accounts only (`CUR_ESSENTIAL`, `CUR_PREMIUM`); password rules of `PasswordPolicy` |

Live events when a customer removes a conversation: a SYSTEM message on
`/topic/conversation/{id}`, `STATUS_CHANGED` → `ABANDONED` when it was live, and
`CONVERSATION_DELETED_BY_CUSTOMER` on `/topic/queue/{skill}`.

Why the one-conversation rule: the AI Advisor answers only assigned or active conversations; a second
parallel conversation stayed queued and got no AI answer (reproduced live).

## 2. Run it locally (without touching Neon)

Requirements: Docker Desktop, Java 21. From this repository:

```bash
# 1. A local database (pgvector image)
docker run -d --name cv-local-pg -p 55440:5432 -e POSTGRES_USER=callverse \
  -e POSTGRES_PASSWORD=callverse -e POSTGRES_DB=callverse pgvector/pgvector:pg16

# 2. Build and start the backend on :8080 (dev profile, demo data, AI off)
./mvnw -q -DskipTests package
SPRING_PROFILES_ACTIVE=dev CALLVERSE_DEMODATA_ENABLED=true SERVER_PORT=8080 \
DB_HOST=localhost DB_PORT=55440 DB_NAME=callverse DB_USERNAME=callverse DB_PASSWORD=callverse DB_SSLMODE=disable \
JWT_SECRET=<any 64+ random characters> INTERNAL_SERVICE_KEY=<any random string> AI_ADVISOR_MODE=OFF \
java -jar target/callverse-backend-0.1.0-SNAPSHOT.jar
```

With the AI: start the AI service with `ai-service/.env` (Groq key, same `INTERNAL_SERVICE_KEY` and
`AI_SERVICE_KEY` on both sides; keys are shared privately, never in git), then add
`AI_SERVICE_BASE_URL=http://localhost:8000 AI_SERVICE_KEY=<same as the AI service> AI_ADVISOR_MODE=AUTONOMOUS`.

CORS allows `http://localhost:3000`: run the frontend there.
